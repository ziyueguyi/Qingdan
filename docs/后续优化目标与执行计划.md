# Qingdan 后续优化目标与执行计划

目标创建：2026-11-12。基线：已发布的 0.3.0；持续目标状态：进行中。

## 第一阶段：提醒与同步稳定性（0.3.1 已发布）

- [x] Android 本地提醒与要求联网的同步 Worker 分开，断网不阻止本地提醒扫描。
- [x] Worker 检查原生桥业务结果；网络故障退避重试，授权/配置问题显示可操作原因。
- [x] 同步网络请求移出长时间业务锁；合并与提交保护保留，并发编辑不能丢失，失败不能清空待推送数据。
- [x] 同步显示运行状态、拉取/推送数量、最后成功、失败和下次重试，设置页打开时保持刷新。
- [x] 用断网/慢网/前后台切换/并发编辑测试验证，并回归 Windows/API/CLI 既有行为。

## 第二阶段：规则与性能（拟 0.4.0）

- [ ] 中国法定节假日和调休工作日：采用有来源及年份版本的数据，可离线使用；缺失年份明确提示，不默认为已知工作日。
- [ ] 重复任务可选跳过该次、顺延到工作日；覆盖周末、调休、连假、跨年、COUNT/UNTIL、月末及两端同步一致性。
- [ ] 主任务视图按页查询，滚动前预取；分组、排序、搜索和日历不得因分页漏项或重复。
- [ ] 长列表按需渲染，建立万条任务性能基线与可重复验收。
- [ ] 点击通知进入对应任务，支持完成和稍后提醒；已删除任务、冷启动及重复任务有明确行为。

## 第三阶段：设备与发布体验

- [ ] Android 省电、锁屏、重启、断网恢复、覆盖升级验收；模拟器和真机证据分别记录，未取得真机不能标记真机通过。
- [x] 修复 CI 截图留存，生成可查看的手机界面产物（0.3.1，详见该版本验收记录）。
- [ ] 应用内检查版本、更新说明及 Releases 页面入口；检查失败不影响离线使用，不静默安装。
- [ ] Windows WebView2 缺失检测、安装引导与诊断。
- [ ] 更新 README、功能方案和验收记录，清理过期里程碑描述。

## 每阶段交付约束

1. 保留既有数据、备份/恢复、墓碑/冲突语义、接口权限和固定 APK 签名；先写兼容方案再修改共享协议。
2. 完成相关单元/集成测试和必要的页面实测，发布前运行全量检查。
3. 按应用版本提交源码，GitHub Actions 构建 Windows EXE 和签名 Android APK，通过后发布到 Releases。
4. 记录真实证据和限制；外部资源缺失时请求资源，不能用模拟验证冒充真机验证。

Windows 代码签名是可选成本项，不自动购买证书。番茄专注、任务模板、桌面小组件和服务端兜底提醒保留为后续候选，不属于本目标必须交付范围。
