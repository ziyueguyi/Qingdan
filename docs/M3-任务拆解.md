### A0 spike 结果

`winotify 1.1.0` 是纯 Python（`py3-none-any`，15KB，**无 cp314 wheel 风险**），但它内部通过 PowerShell 调 WinRT，所以「装得上」不等于「弹得出」。实测：PowerShell 5.1.22621 在位、`show()` 无异常、服务里 `alert.status` 回报 `backend: "winotify"`，前端点「发送测试」后 `alert.log` 记到 `测试：ok`。**请你确认桌面是否真的出现了通知**——程序侧只能证明调用没抛错。
降级链已实现：winotify → `ctypes` MessageBoxW（独立线程，避免阻塞调度循环）→ 报不可用。

### 实跑中发现并修掉的问题

| 问题 | 性质 | 现在的守卫 |
|---|---|---|
| `_merge()` 浅拷贝，导致关闭渠道会**永久改写进程内 DEFAULTS** | 真生产 bug：第一个用户关掉 toast 后，全新数据库也继承 toast=False | `test_defaults_are_never_mutated` |
| 调度器问「渠道自己开没开」而不是问配置 | 关掉的渠道仍会生成作业，留下一堆无意义 failed | `_enabled_channels()` 改为以配置为准 + `test_channel_disable_stops_jobs` |
| 钉钉/邮箱未配置时 UI 显示「该功能属于 M3，尚未实现」 | 文案错误：渠道已实现，只是没填 | 拆成 `alert_not_configured` / `not_impl` 两个键 |
| `_sync_alerts` 里裸 `except Exception: pass` | 吞掉真实异常，排查时完全看不见 | 保留兜底但用探针脚本 `spike/alert_probe.py` 定位 |

另外契约测试这次真的发挥作用的两处：注入假渠道（否则 `alert.channel_test` 会往你桌面弹通知），以及发现**路径参数被同名 query 劫持**——`/alert/channels/{name}/enable` 里 `name` 既是路径参数又可能出现在 query 里，dispatcher 原本是 query 覆盖 path，已改成**路径参数有最终决定权**。

### 已实现清单

### A0 / A9.6 结论：winotify 这条路当前不可用，已改默认后端

实测链条：winotify 装得上（纯 Python，无 wheel 风险）→ `show()` 不抛异常 → 直接跑它内部那段 PowerShell 得到 `SHOW_CALLED_OK` → **但用户桌面没有任何通知**。

两层静默失败叠加：
1. **Windows 会丢弃非打包应用发的 toast**（没有 MSIX 身份、没有带 AUMID 的开始菜单快捷方式），且不返回错误。
2. winotify 自身 `_run_ps` 用 `Popen(stdout=DEVNULL, stderr=DEVNULL)`，**不 wait、不查 returncode**，Python 侧永远看不到失败。

处理：`toast.backend` 变成显式配置（`dialog` / `toast` / `auto`），**默认 `dialog`**（`MessageBoxW`，实测一定能看见），`toast` 留给 M6 打包并注册 AUMID 之后再切。多条提醒合并成一个对话框，不弹 30 个模态框。

### 又抓到一个只有真发送才会暴露的 bug

`config.get_config()` 返回的是 **DPAPI 密文**（`dpapi:` 开头），而钉钉适配器用它判 `startswith("https://oapi.dingtalk.com")` —— 永远 False，导致明明配好了却报「未配置」。改成 `get_config()` 解密后交给适配器、`get_public_config()` 脱敏给接口层，并区分「密文解不开」（换机/换用户）与「根本没填」，前者通过 `alert.status.secret_errors` 上报。

这条 bug 单元测试永远撞不到——因为测试里喂的是假配置字典。所以补了 `test_get_config_decrypts_for_adapters`，**强制走真实 protect/unprotect 路径**。

## 前置事实（已核实，写进设计不再讨论）

| 事实 | 影响 |
|---|---|
| 钉钉自定义机器人 **20 条/分钟**，超限封禁 10 分钟 | 必须令牌桶 + 同分钟合并成一条 markdown，不能一条提醒发一条 |
| 钉钉业务错误返回 **HTTP 200**，真因在 body 的 `errcode/errmsg` | 只看状态码会把「关键词不匹配 310000」当成成功；UI 必须原样显示 errcode |
| 钉钉加签 = `urlencode(base64(hmac_sha256(secret, f"{ts}\n{secret}")))` | 有固定测试向量才能自证正确 |
| QQ/163 发信要**授权码**不是登录密码，且境外 IP 易风控 | 配置项要写明；一封汇总，不一条一封 |
| 补发轰炸：关机一天后开机，历史提醒会一次性涌出 | `fire_at < now-10min` 一律 `skipped`，只补今天未过期的 |

### A0 Windows 通知机制 spike（阻塞项，先做）

`winotify` 走 WinRT 绑定，Python 3.14 wheel 未必齐；装不上就要立刻换方案，否则 A4 写完才发现发不出。

候选与降级顺序：
1. `winotify`（纯 Python，toast 样式最正规）
2. `ctypes` 调 `user32.MessageBoxW` 到独立线程（零依赖，但是模态框，样式差）
3. 应用内浮层（前端渲染右上角卡片 + `Audio` 提示音）——**这个一定能成**，作为兜底
4. 三者都保留：能系统通知就系统通知，否则应用内浮层，UI 上说明当前用的是哪种

验收：在打包后的 exe 环境（非源码运行）能弹出一次可点击的通知。

### A2 调度器

| # | 任务 | 要点 |
|---|---|---|
| A2.1 | `alert_job` 表落库 | 字段：item_id / fire_at / channel / status / attempts / next_retry / dedup_key UNIQUE |
| A2.2 | **幂等重建** | 每次任务保存后：删掉该 item 的 pending 作业，按 `remind_at × 启用渠道` 重新生成。作业是派生数据，不是真值，删了能重算 |
| A2.3 | 扫描循环 | 进程内线程，每 20s 扫 `status=pending AND fire_at<=now`；fan-out 到各适配器 |
| A2.4 | 去重 | `dedup_key = item_id:fire_at:channel` 唯一约束，重启/补扫不会重发 |
| A2.5 | 补发防轰炸 | 启动时把 `fire_at < now-10min` 的 pending 全标 `skipped` |
| A2.6 | 免打扰 | 时段内不响铃、**过期不补发**；只落日志 |
| A2.7 | 持续提醒 | `remind_mode=sticky` 未处理则每 60s 重发，直到完成/推迟 |
| A2.8 | 失败退避 | 单渠道失败 `attempts++`，指数退避 1/5/15 分钟，3 次后 `failed` |
| A2.9 | 不污染同步 | 生成/更新 alert_job **绝不能**把 item 标成 dirty（有测试守着） |

### A3 渠道框架

```python
class AlertChannel(Protocol):
    name: str
    def is_configured(self) -> bool
    def enabled(self) -> bool
    def send(self, msgs: list[AlertMessage]) -> SendResult   # 注意是复数：支持合并
    def test(self) -> SendResult                              # 设置页「发送测试」，必须实现
```

- 适配器注册表：新增渠道 = 一个适配器 + 一个 `@feature`，主链路零改动（给飞书/企微留位）。
- **`send` 收列表**是刻意的：合并发送是硬需求，接口形状必须先支持，否则后面要改所有调用点。
- 每渠道独立成功/失败，一个渠道挂了不影响其他。

## 风险

1. **toast 机制**（A0）——唯一可能改方案的点，先 spike。
2. 钉钉限流是**按机器人**计数，不是按消息；如果用户把多个应用共用一个机器人，仍可能被别的应用打满。缓解：合并发送 + 令牌桶留 20% 余量。
3. DPAPI 密文**绑定当前 Windows 用户与本机**：换机或重装系统后密钥失效，需要用户重新填。这是设备本地配置的应有之义，但要在 UI 上说清楚，别让人以为备份数据库就能带走密钥。
4. 提醒只在进程活着时生效 —— 这是 M7（服务端兜底）的范围，M3 不做，UI 上要诚实标注。
