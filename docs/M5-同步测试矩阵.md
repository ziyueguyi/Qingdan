### 真实 Gitee 端到端验收（`scripts/verify_gitee_live.py`，2026-11-05 PASS）

假 API 只能证明分支对，证明不了 Gitee 认这套凭据。真跑七步：

1. 登录（顺带拿到服务器时钟偏差 -150ms，供 HLC 校正）
2. `repo.ensure` 命中已存在的私有仓，`private=True`
3. 建分组/任务/倒数日 → `sync.run` → 推上去
4. **另开工作副本直接从远端读回**（不信本地缓存）核对文件清单
5. 第二轮 `sync.run` → `pushed=0`（幂等）
6. 改一条 → 同步 → 远端内容确实跟着变
7. 删一条 → 同步 → 远端留下 `"deleted": true` 的墓碑，而不是文件消失

### 验收里踩到的一个坑，值得记下来

第 6 步第一次跑失败了：push 报成功、`refs/heads/master` 也更新了，但读回来看不到改动。

原因是**验收脚本**把 `fetch()` 之后又去读 `head()`。`fetch` 按设计**不移动本地分支**
（我们不用 `pull`，合并发生在应用层），所以 `head()` 还是本地旧位置。
已在 `GitRepo` 上补 `remote_head()` 并把这条写进 docstring —— 这是个会反复咬人的语义陷阱，
光靠"记得用返回值"不够。

### D1 的设计判断

回收墓碑会撕掉「删除发生过」这个证据。之后一台离线超过窗口的机器带着**比删除更晚的本地编辑**
上线，按 LWW 判会**静默复活**已删项。

解法：回收时同时写 `graveyard.json` 名册，记下每一项的最后墓碑版本。同步时先查名册：

- 名册里有 → 已确认删除 → 本地维持已删；若本地编辑更新，**把编辑存进 conflict 但不复活**，
  由用户在冲突界面决定是否恢复。删除决定是权威的，但用户的劳动不能丢。
- 名册里没有 → 协议外手工删除 → 走 B4 的 keep + 告警。

**同样是"文件不见了"，这两种情况语义完全相反**，混了就会误删用户数据 —— D3 就是专门测这条边界的。

处理顺序也是硬约束：名册必须在 `_push` **之前**应用。放后面的话 `_merge` 已经判了
"本地更新胜出"，会先把复活结果推上远端。

## 本轮实现中改掉的两个缺陷

1. **`_merge` 无条件记冲突**，没用上 `merge.should_record_conflict` —— 导致"两边都删"
   （A11）会弹一个无意义的冲突。测试 `test_double_delete_is_silent` 抓到。
2. **本轮无改动时本地分支不对齐远端 head**，工作区永远落后一截，表现为两台机器的
   tree 不一致（B11 收敛性被破坏）。修成无改动也 `reset_to(remote_head)`。

## 三条测试本身写错、但暴露了真实认知的地方

- **B7 撞车**：普通的"b 后同步"根本不会冲突——b 的 sync 一开始就 fetch 到 a 的新提交了。
  真冲突只发生在 **fetch 与 push 之间的窗口**。所以测试必须用桩把第一次 fetch 的结果
  变旧才能复现。这个认知不写出来，以后会误以为冲突路径已被覆盖。
- **B4 协议外删除**：顺序必须是「先同步拿到 base → 远端被手工删 → 再同步」。
  反过来（新机器先遇到缺失）根本没有 base 可比，检测不到任何东西。
- **守卫测试用子串匹配**会把自己文档里那句"`porcelain.pull` 在分叉时抛异常"判成违规。
  改成 AST 找真实调用 —— 有假阳性的守卫测试，下一次改动时就会被当噪音删掉。


## 残余风险（矩阵覆盖不到的）

1. **dulwich HTTPS 推送**未经真实验证（本地裸仓库走的是 file 协议）。Gitee 侧还有
   "改密码/开两步验证后令牌失效"的历史行为 —— M4 第一天必须验。
2. **git 历史无限增长**：每次同步一个 commit，5 年约几十 MB，500MB 单仓上限内安全，
   但**附件**会立刻撑爆（这也是 v1 不做附件的原因之一）。
3. **并发写同一 item** 的字段级丢失：v1 用整条 LWW，A 改标题 + B 改备注同时发生时，
   只有一条改动存活。已留 `fields_updated_at` 字段位，二期做字段级合并。
4. 系统时钟被人为大幅调后（比如改到 2020 年）再调回，`observe` 能保护但不覆盖
   所有路径；`clock_skew_ms` 超阈值应拒绝 push，这条在 M4 实现。
