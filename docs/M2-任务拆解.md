目标：`qingdan serve` 起服务后，浏览器/pywebview 打开的就是**真应用**，看到的每一条任务都来自 SQLite，每一次点击都走 `@feature` 接口。原型 `清单exe-界面原型.html` 里的内置演示数据全部退役。

## 一条前置原则

**前端不写任何 URL。** 启动时拉一次 `/api/v1/meta/features`，得到「功能名 → 方法 + 路径模板」的映射，之后只调用 `call('task.create', {...})`。这样后端加接口，前端零改动；前端也不会因为手抄路径抄错而 404。这是 R4「接口即唯一入口」在前端的体现。

## 风险

1. **竞态**：视图切换与写操作并发，慢响应覆盖新视图 —— B2.3 用请求序号解决，不能省。
2. **乐观更新与版本戳**：UI 先改本地再等后端返回，若后端返回的 rev 与本地猜测不同，撤销/同步判断会错。决定：**一律以后端返回为准**，UI 不做乐观更新（清单量级下延迟不可感知，正确性优先）。
3. **静态资源与 API 路由打架**：挂载顺序错会让 `/api/v1/...` 被 catch-all 吃掉，B1.2 要有断言。
4. **前端文件膨胀**：原型是单文件，真应用拆 6 个文件后容易互相缠绕；坚持 `store → render` 单向，禁止在事件处理里直接改 DOM。
