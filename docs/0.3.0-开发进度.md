# 0.3.0 开发范围与进度

当前用户要求（持续推进，不以某个子项完成替代全部交付）：

1. Android 独立离线 APK，尽量复用任务/清单/标签/过滤器/重复规则/本地 SQLite 与 Gitee 增量同步。
2. 可设时间的定时双向增量同步：间隔分钟，或每天多个 HH:mm 时间；记录下次执行与上次结果。桌面进程内调度，Android WorkManager 后台调度，说明系统省电导致的延迟。
3. API 支持 HTTP 无证书、HTTPS 自动自签名或导入证书，以及 HTTP/HTTPS 双端口；保留 Bearer Token 和接口授权。
4. 设置中 API 与 CLI 分开；API 四个子页为远程服务、Token 管理、创建 Token、调用日志（用户已明确确认）。
5. Token 表格列：Token（仅掩码，原文仍只展示一次）、调用统计、使用期限、QPS、调用限制、创建时间、最近使用、状态、备注、操作。补齐逐 Token 限流和调用配额，不只显示空字段。
6. 验证 Windows 既有功能，构建安卓 APK 与更新 Windows EXE，提交 GitHub 并在 Releases 提供两种系统的软件包。
7. 用户追加要求使用最新 Android：按官方稳定版 Android 17 QPR2 设置 compileSdk 37.2、targetSdk 37 及 37.2 / 16 KB 页模拟器；构建工具 37.0.0、AGP 9.5、Gradle 9.6，并保留 minSdk 24 的旧机兼容。官方依据：https://developer.android.com/about/versions/17/setup-sdk 。

已实现：可配置定时同步、HTTP/HTTPS 双端口与自动证书、Token QPS/配额/备注、API/CLI 拆页与四个 API 子页。Windows 全量回归 762 项通过；包含真实双协议自动证书及定时全类型增量同步。正在做浏览器实际操作和安卓构建验证，尚未交付新版本。

Android 路线：原生 Java Activity + WebViewAssetLoader 加载本地网页；Chaquopy 17.2 / Python 3.13 承载同一 Python core；用异步原生桥调用 registry，避免 FastAPI/Pydantic 的 Android 原生轮子依赖。凭据通过 Android Keystore AES-GCM 加密；WorkManager 后台同步；原生通知与文件导入/分享；手机布局单独适配。构建环境通过 GitHub Actions（本机只有 adb，没有 Java/SDK）。纯 Python Dulwich 源文件与 httpx/urllib3 依赖需要验证，可从构建环境安装的 Dulwich 排除可选 Rust 扩展后复制，使用其已提供的纯 Python 回退。

安卓工程、手机布局、Keystore 加密、通知、文件导入分享、WorkManager 和模拟器烟测已写入；固定签名已本地生成，四项 CI 签名 Secrets 已配置且在仓库页面验证存在。签名备份在 .private/android-signing 下，不入 Git。代码已提交 GitHub。浏览器已验证 API 四页、Token 表格十列、原文只显示一次、QPS/配额/备注、HTTP 无证书、双端口和 CLI 独立页；定时同步按每天 09:15、18:45 实测保存并核对后端。云端 arm64 签名 APK 和模拟器 APK 已编译成功；首次模拟器测试发现 Windows 自启接口影响 Android 页面启动，已隔离并重跑。Windows 云端全量回归、打包、体积与冻结包运行检查成功。尚待本轮 Android 运行测试及统一发布完成。
